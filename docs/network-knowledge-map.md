## 一、约定与图例

### 1.1 知识点编号

`NET-<模块号>-<序号>`，例：`NET-04-08` = 模块 04（传输层）第 8 个知识点（TCP 三次握手）。编号一经分配**不再复用**，删除的知识点保留空号，避免外部引用失效。

### 1.2 列含义

| 列 | 含义 |
|---|---|
| 层级 | 初级（入门必学）/ 中级（岗位常用）/ 高级（专题深入） |
| 主教材 | Top-Down 9E 的章节号（已核对目录）。`—` 表示该教材没有对应小节，只能靠标准或厂商文档 |
| 标准/工程依据 | RFC / IEEE / 厂商文档。⏳ 表示该编号**尚未核对当前状态**（不得直接写入正式内容） |
| 动画 | 固定动画适配度：★★★ 第一阶段可做 / ★★ 可做但需要新的表达能力（广播、多跳、多参与者）/ ★ 暂不建议做动画 / — 纯概念，不适合动画 |
| 实验 | 交互实验适配度：Ⅱ 第二阶段（参数可配置）/ Ⅲ 第三阶段（自建拓扑）/ — 暂不做 |

### 1.3 动画适配度的判定口径

不是"好不好看"，而是**当前渲染引擎能不能表达**：

| 需求 | 现状（第一阶段开始时） | 结论 |
|---|---|---|
| 4 个参与者以内、单源单目的、顺序推进 | 已支持（TCP 演示即此形态） | ★★★ 可直接做 |
| 一对多（广播 / 组播 / 泛洪） | 需扩展"多目标事件" | ★★ 先扩展模型再做 |
| 5 个以上参与者（DNS 全链路、OSPF 多路由器） | 需扩展"参与者数量可变" | ★★ 先扩展模型再做 |
| 无报文、纯状态/纯概念 | 引擎以报文为中心 | ★ / — |

## 四、依赖与关联关系

### 4.1 主干依赖链（必须先学左边）

```
M01 基础（分层/封装/协议）
  ├─→ M02 链路层 ──→ ARP ──→ 默认网关（M03）
  ├─→ M03 网络层 ──→ 路由表 ──→ M06 路由协议
  │        └─→ NAT ──→ 出口网络（M09）
  ├─→ M04 传输层 ──→ 端口/多路复用 ──→ M05 应用层
  └─→ M07 安全（依赖 M04 TCP 与 M05 TLS）
```

### 4.2 强依赖（B 不理解就无法讲 A）

| 知识点 | 必须先掌握 | 原因 |
|---|---|---|
| NET-02-18 ARP | NET-03-02、NET-03-07 | 不讲"是否同网段"，就无法说明"解析目标主机还是网关" |
| NET-03-16 路由转发 | NET-02-05（MAC）、NET-03-09（TTL） | 逐跳转发时 MAC 变、IP 不变、TTL 递减是同一个动作的三个侧面 |
| NET-03-15 最长前缀匹配 | NET-03-04、NET-03-05 | 没有掩码/CIDR 概念，前缀长度无从谈起 |
| NET-04-08 三次握手 | NET-04-07（标志位）、NET-04-11（序列号） | 否则 SYN/ACK 只是两个抽象字母 |
| NET-05-04 DNS 查询 | NET-05-05、NET-05-06、NET-05-07 | 递归/迭代/缓存是同一张图的三条路径 |
| NET-05-17 DHCP | NET-01-10（广播） | DORA 的广播/单播组合必须靠广播域概念解释 |
| NET-06-06 OSPF 邻居 | NET-03-17（ICMP 之外的协议报文）、NET-06-08（Hello） | 邻居建立由 Hello 驱动 |
| NET-07-09 数字证书 | NET-07-10（非对称加密）、NET-05-16（TLS） | 证书是"公钥 + 身份绑定"的载体 |

### 4.3 易混淆对（内容必须成对出现，避免单边解释）

| A | B | 关键差异 |
|---|---|---|
| NET-04-16 流量控制 | NET-04-18 拥塞控制 | 前者保护**接收方**，后者保护**网络** |
| NET-05-05 递归查询 | NET-05-06 迭代查询 | 谁承担继续查询的责任 |
| NET-02-11 VLAN | NET-02-13 Trunk | 前者是广播域划分，后者是跨设备承载多个 VLAN |
| NET-03-19 Traceroute | NET-03-18 Ping | 前者利用 TTL 耗尽，后者利用 Echo |
| NET-04-14 超时重传 | NET-04-15 快速重传 | 触发条件：RTO 到期 vs 收到 3 个重复 ACK |
| NET-02-15 STP | NET-09-16 网络环路 | 前者是机制，后者是故障现象 |

## 五、推荐学习顺序

### 5.1 路径 A：教材主线（自顶向下，按 Kurose 章节）

`M01 概览` → `M05 应用层`（HTTP → DNS → DHCP） → `M04 传输层`（TCP/UDP） → `M03 网络层`（IP/路由/ICMP） → `M06 控制平面`（OSPF/BGP） → `M02 链路层`（以太网/VLAN/ARP） → `M08 无线` → `M07 安全` → `M09 工程实践`

理由：先看到"用户能感知的结果"（网页、域名），再往下追问"靠什么保证"，符合 Top-Down 的教学动机。

### 5.2 路径 B：认证与工程主线（自底向上）

`M01` → `M02`（MAC/VLAN/STP/ARP） → `M03`（IP/掩码/网关/路由表） → `M06`（OSPF/BGP） → `M04`（TCP/UDP） → `M05`（DNS/DHCP/HTTP） → `M07` → `M08` → `M09`

理由：与 CCNA/HCIA 类认证的知识顺序一致，适合"先能配设备，再懂原理"的学习者。

### 5.3 路径 C：排障实务线（问题驱动）

`M01` → `M03`（连通性：IP/掩码/网关/路由表/ICMP） → `M02`（同网段不通：VLAN/ARP/环路） → `M05`（能通但打不开：DNS/DHCP/HTTP） → `M06`（跨域不通：路由协议） → `M09`（故障案例库）

理由：对应真实工单的排查顺序（物理 → 二层 → 三层 → 应用），也直接决定 M09 的案例编排。

### 6.2 需要先扩展表达能力（★ ★）

| 演示 | 阻塞点 | 需要的模型能力 |
|---|---|---|
| **ARP 地址解析** | ARP Request 是广播（1 → N），且同一广播域内其他主机必须"收到但不回复" | **多目标事件** + "收到但不处理"的显式状态 |
