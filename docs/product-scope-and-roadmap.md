> 版本 **V1.1** · 2026-11-12 · 基线 `b5171bd`（M2-P0 已通过独立审计）
> V1.0 只做评估；**V1.1 记录 D-A…D-E 的确认结果与落地方式**（§10），并新增 M2-A 施工图 `docs/m2a-implementation-plan.md`。

## 0. 一页结论

| 问题 | 结论 |
|---|---|
| 产品是什么 | 网络原理**动画教学站**：多课程、可扩展，播放器一套，内容靠数据驱动 |
| 产品不是什么 | 不是网络模拟器 / 实验平台 / 协议计算器；不做参数编辑、拓扑编辑、故障注入 |
| 现有架构是否要推翻 | **不推翻。** 9 项资产中 8 项当前必需（3 项降载运行）、1 项冻结；协议计算层**根本没有，也不该建** |
| 最大的真实风险 | 不是"抽象太多"，而是 **渲染层仍是 4 槽位 + 索引语义**，与新模型的 `id` 语义之间缺一层薄适配（估计 150–200 行） |
| 播放器能否直接复用 | **能。** `app.js` 本来就是多课程播放器（分组导航、搜索、hash 路由、进度都在），只是本构建把入口裁掉了 |
| M2-A 要不要重写播放器 | **不要。** 只加一层 `demo → viewModel` 适配 + 把 14 步搬进 JSON |
| 架构上现在该做什么 | **冻结数据层**（只修 bug、不加抽象），把精力全部投到 M2-A 的适配层与内容 |
| 判定是否成功的硬指标 | M2-B 结束后，加一门课 **`src/` 零改动**（或仅一处注册表），否则就是架构失败 |
| 五项决策 D-A…D-E | **已确认**（2026-11-12，用户批准）。落地方式见 §10，施工细节见 `docs/m2a-implementation-plan.md` |
| 当前该做的下一件事 | **M2-A**：TCP 主/备用场景迁移 + 适配层 + 状态文案 fold 派生 + 报文行绑定修复 + 导航入口恢复（单课时隐藏） |

## 1. 最新产品定位

### 1.1 一句话定位

> 把一条协议、一次交互、一段状态变化，用**可播放的等距动画 + 逐步文字 + 报文表**讲清楚；
> 一套播放器承载全部课程，课程本身只是数据。

### 1.2 三条边界线

| 线 | 在内 | 在外 |
|---|---|---|
| **内容线** | 既定好的演示时间线（数据写死）、逐步解释、报文七列表、来源与知识正文 | 用户改参数后**重算**行为、实时协议栈、任何"根据输入推导报文"的能力 |
| **拓扑线** | 每课自带一张固定拓扑（3–6 个设备），演示期间不变 | 用户增删设备、连线、划 VLAN、配路由；动态拓扑变化 |
| **交互线** | 播放/暂停/单步/重置/变速/跳步/知识点联动/详情联动的**展示层**交互 | 故障注入、实验任务、评分与验证、结果对比 |

一句话：**观众是来看懂的，不是来操作的。** 所有交互都服务于"看懂"，不服务于"改配置"。

### 1.3 成功标准（可验证，不看感觉）

1. 一门新课上线，改动集中在 `content/`，`src/app/`、`src/isokit-*.{jsx,mjs}` 的 **diff = 0**。
2. 任何一课的播放体验与现有 TCP 演示**同构**：同一套控件、同一套表格列、同一套图例逻辑、同一套响应式断点。
3. 新增一课不需要新的 `if (protocol === 'xxx')` 分支。
4. 全站 `npm run check` 绿，且课程数量变化不影响检查脚本源码。

### 1.4 与旧计划书的差异（哪些章节降级）

| 旧计划书章节 | 原定位 | 新定位 |
|---|---|---|
| §三 九大模块 / 165 知识点 | 一次性建成知识体系 | **降级为内容路线图**：先 1 模块（传输层）跑通，其余按需 |
| §6.3 交互实验模板 | 实验（参数 + 预期/实际对比 + 结论） | **移出第一版**（见 §3） |
| §4.2 ARP 7 项交互 / §4.3 DNS 7 项交互 | 交互实验 | 降级为**动画演示**（ARP 广播/单播过程、DNS 递归/迭代链路） |
| §五 `labId` 字段 | 实验关联 | 字段保留（已在类型里），**永不实现**，不投入 |
| §8 版权与商业化 | 商业化前置 | 保留 P 门禁（已在 M2-P0 落地），但不为它加新抽象 |

## 3. 明确排除的功能

| 排除项 | 为什么不做 | 将来若真要做的最小入口（现在不实现） |
|---|---|---|
| 改 IP / 掩码 / 网关 / 端口 / 序列号 | 一旦可改，就必须有协议引擎算结果，架构性质变了 | 无。真要做时是另一个产品 |
| 自定义拓扑 / 增删设备 / 连线 | 渲染层要为任意拓扑做自动布局，成本远超教学收益 | 数据里预留 `topology` 已足够表达"每课一张固定图" |
| 配 VLAN / 路由 / 交换机 | 属实验平台能力 | 无 |
| 按输入实时计算协议行为 | **协议计算引擎永远不进第一版** | `src/protocol/*.mjs`（旧架构分析 §7-3 的建议）**正式搁置**，不建目录 |
| 网络模拟引擎 | 与产品定位直接冲突 | 无 |
| 故障注入 / 实验执行 | 需要可信的失败模型 + 结果判定 | 现有 `drop` 事件 + `alternate` 场景已能讲"丢了会怎样" |
| 实验任务管理 / 评分 | 需要账号、提交、批改 | `labId` 字段留着，不实现 |
| 参数面板 / 预期-实际对比 | 属实验模板（计划书 §6.3） | 整个模板移出第一版 |

**代价说明**：排除这些之后，`docs/architecture-analysis.md` §5 差距矩阵里标为"第五阶段"的 5 行（§6.3 交互实验、§4.1 五个扩展实验、§4.2/§4.3 参数交互）**全部作废**。这不是遗漏，是刻意放弃。

## 4. 当前架构必要性评估（9 项 → 三类）

### 4.1 分级表

| # | 架构项 | 分类 | 依据 | 处置 |
|---|---|---|---|---|
| 1 | Knowledge / Source / Demo 三表分离 | **当前必需** | 第 10 项功能（课程目录 + 知识 + 来源）的唯一落点；也是"加课不改码"的前提 | 保持 |
| 2 | TypeScript 类型定义 | **当前必需** | 4 份真实内容（TCP/ARP/DNS + 后续）一旦手写 JSON 必然漂移；`tsc --noEmit` 是唯一的编译期防线 | 保持，**冻结**：只允许 M2-A 发现的"必需字段"，禁止顺手加 |
| 3 | Zod Schema 校验 | **当前必需** | JSON 无类型，运行时必须拦；L1 已证明能拦 12 类缺陷（M2-P0 测试） | 保持，冻结 |
| 4 | 引用校验 + 发布门禁（X1–X14 / P1–P7） | **当前必需（降载）** | 引用校验必需（防"引用了不存在的来源/演示"）；P 系列门禁在**只有 1 课时几乎空转**，但成本已沉没、无维护负担 | 保持，**M2-A 起随真实数据自动生效**（见 9.3） |
| 5 | 事件 + TargetSpec 模型 | **当前必需（子集）** | 第一版只用 `unicast / process / drop` + `device` 目标；`broadcast` 供 ARP、`multicast` 供后续 | 保持，`multicast` **冻结**（N1 修好的校验留着当护栏） |
| 6 | `dependsOn` + 波次推导 | **保留但暂不扩展** | 第一版是**逐步播放**：一步一事件，线性推进，不需要拓扑分层；波次只在"一步多事件"时才有意义（当前 0 处使用） | 保留 `waves.ts`（93 行，已有测试），**不投入**；M2-A 不接它 |
| 7 | `StateDelta` + `fold-state` | **当前必需** | 第 5 项功能（设备状态随步骤变化）的唯一可信来源；也是"状态观察"文案的派生依据，避免 14 条文案与报文相互打脸 | 保持（M2-A 真正开始用它） |
| 8 | React / IsoKit 播放器 | **当前必需** | 全部视觉资产都在这（等距设备、路径、双箭头、拖尾、丢失）；重写等于重做产品 | 保持，**只加适配层**，不动美术逻辑 |
| 9 | 课程内容组织方式 | **当前必需（部分要改）** | `content/demos/*.json` + `content/knowledge/*.json` 目录结构必需；但 `MECHANISM_DETAILS` 仍与演示同体，违反"知识/演示分离" | 目录保持；**M2-A 迁 1 篇 knowledge，M2-B 全量拆** |

### 4.2 一个必须正视的量化事实

| 层 | 代码量 |
|---|---|
| 数据层（types 419 + schemas 476 + engine 272 + 校验器 592 + 测试 361） | **2120 行** |
| 播放器 + 内容（app.js 120 + scene 201 + model 126 + dot/motion 98 + data 430 + mechanisms 40） | **1015 行** |

数据层的代码量已经是**整个播放器与内容的两倍**，而它目前承载的真实数据是 **0 课**（`content/demos/` 为空）。

这不是说数据层做错了——M1 的审计已证明它对 N1–N7 是真防线——而是说明：**抽象的红利还没兑现，成本已经付完。**
因此本次校准的核心动作就是一句话：**冻结数据层，把抽象红利兑现成内容。**

具体冻结规则（写进团队约定，比写进文档更管用）：

1. 不给 `src/types`、`src/schemas` 加"将来可能用到"的字段；
2. 不给校验器加新规则码（X15、P8…），除非 M2-A/B 撞上真实缺陷；
3. 不把 `waves.ts` 接进播放器（第一版线性播放不需要）；
4. 不为"实验/参数/拓扑编辑"预留任何新类型。

**冻结例外登记（M2-A 施工时提出，逐条留痕）**

| 例外 | 为什么"当前必需" | 为什么没有替代字段 |
|---|---|---|
| `Step.caption?: string` | 场景字幕（`#step-description`）与右侧逐步详解（`#detail-content`）是**两段不同的文本**，现站分别是 `s[4]` 和 `stepNotes[i]` | `Step.description` 按类型注释已承载深注；事件 `note` 承载状态观察；无第三处可放 |
| `Source.description?: string` | 「来源」页签卡片需要一句"该来源在教学里起什么作用" | `licenseNote` 语义是授权约束，不能当描述用；`name`/`author` 已另有含义 |
| `Device.stateLabel?: string` | 状态观察文案要用短名（现站是「服务端」，而 `Device.label` 是「Web 服务器」；设备标签不能改，会动像素） | 由 `role` 推中文（`server → 服务端`）属把文案写进代码，ARP 的两个 host 立刻歧义 |

另有 `Step.signal?: string`（本步"信号行"，无报文的本机动作步骤需要它，例如备用演示末步的 `TIME_WAIT 2×MSL`；缺省回退 `event.payload.summary`）。现站共有四个独立文本槽位（标题 / 信号行 / 场景字幕 / 逐步详解），模型只有两个，补齐这两个不是创新，是把**既有 UI 契约显式化**。

四条均为**可选字段**、只进类型与 Zod、**不新增任何校验规则码**；缺省语义在方案里写死（`signal` 回退 `payload.summary`、`caption` 回退 `description`、`description` 缺省不显示、`stateLabel` 回退 `label`）。若审查认为例外过多，可整批退回，代价是 M2-A 必须接受四处可见文案变化并重做基线。

### 4.3 当前**不需要**的东西（明确停投）

| 项 | 现状 | 判定 |
|---|---|---|
| 协议计算层 `src/protocol/` | **不存在** | 不建。旧架构分析 §7-3 的建议作废 |
| 实验/参数/任务系统 | 不存在，仅 `labId?: string` 字段 | 字段留着，不实现 |
| `multicast` 渲染 | 模型有、校验有、渲染无 | 冻结。`arp` 用 `broadcast` 就够 |
| OSPF 邻居表 / VLAN 表 | 类型与 schema 有 | 冻结（M2-B 若讲路由再说） |
| 知识图谱视图 `#knowledge-map` | 代码在（`app.js:87-101`），DOM 已删 | **第一版不恢复**（决策 D-D） |
| 发布门禁的复杂分支（P4/P6） | 已实现 | 保留，不扩 |

### 5.3 哪些功能尚未迁移到新架构

严格说，**没有任何一个"功能"被迁移到新架构**——新架构目前只有数据层（类型/schema/校验/引擎），**渲染与播放仍 100% 吃旧数据格式**：

| # | 约束 | 位置 | 说明 |
|---|---|---|---|
| C1 | 设备位置固定 4 槽，按**槽位序号**选美术 | `isokit-model.mjs:2,8`；`isokit-scene.jsx:116,129` | `DEVICES[index]` —— 设备外观由"它是第几个"决定，而不是 `Device.kind` |

### 5.5 新数据模型是否足以描述原网站的动画？——**基本够，6 处缺口**

逐字段核对（现有 14 步 TCP 的每一个视觉要素）：

| 现有视觉要素 | 数据来源 | 新模型字段 | 结论 |
|---|---|---|---|
| 设备名 + 地址 | `nodes[4]` / `addresses[4]` | `Device.label` / `Device.address` | ✅ 一一对应，且 `kind` 比"槽位"更准确 |
| 起点 → 终点 | `s[1]` / `s[2]` 槽位号 | `event.from` + `TargetSpec.device.id` | ✅ 语义更强（id 而非位置） |
| 信号行（`FIN, ACK Seq=79 Ack=2921`） | `s[3]` | `Packet.summary` | ✅ |
| 逐步解释 | `s[4]` + `stepNotes[i]` | `Step.description` | ✅（深注 = `description`，非双份） |
| 关系类型（8 种语义） | `s[6]` | `EventKind` 只有 5 种（`unicast/broadcast/multicast/process/drop`） | ❌ **G2** |
| 状态文案（`客户端 TIME_WAIT · 服务端 CLOSED`） | `s[5]` 手写 | 无字段；但可由 `tcp-state` delta 折叠派生 | ❌ **G1**（半缺口） |
| 表格：时间/源/目的/协议/信息/大小 | `net.main[i]` | `Step.traceRow` | ⚠️ **G3/G6**（size 是 `"66 B"` 字符串 vs `number`；`traceRow` 可选而表格按索引 1:1） |
| 表格类别色（hand/cdata/sdata/fin/lost） | `net.main[i].cat` | `PacketCat` | ✅ |
| 场景（主/备用） | `steps` / `fault.steps` | `scenarios[]`（id + label） | ✅ 更强（支持 N 个场景） |
| 伪代码 | `scenarios[].code[]` | 无字段 | ❌ **G4**（且 UI 已无该页签 → 建议放弃） |
| 关键取舍 / 容易误解 | `tradeoff` / `pitfall` | `Knowledge` 无对应字段（有 `commonProblems[]` 但语义不同） | ❌ **G5** |
| 原理 / 摘要 / 关联阅读 | `principle/summary/readings` | `principle/summary/sourceRefs` | ✅ |

**6 个缺口的处置建议（都不改模型，全在适配层/内容层解决）**

| 缺口 | 建议 | 是否阻塞 M2-A |
|---|---|---|
| **G1 状态文案** | 派生（推荐）：`fold(stateDeltas)` → `设备名 + tcp-state.to`；只有"仍可发送""半关闭"这类附注才手写进 `event.note` | 否 |
| **G2 关系语义** | 适配层放一张 7→5 映射表：`request/data → unicast.payload.cat 或 event.kind`、`local → process`、`lost → drop`、`reject → drop + lost 视觉`、`compare → process`（对照态）；**不新增模型字段** | 否 |
| **G3 size 类型** | 适配层 `size: n` → `"n B"`（展示格式化） | 否 |
| **G4 伪代码** | 删除 `app.js:58` 死分支与 `code` 相关内容（决策 D-C） | 否 |
| **G5 取舍/误解** | `pitfall → commonProblems[0]`，`tradeoff` 暂不迁移（或并入 `why`） | 否（可 M2-B 再定） |
| **G6 表格行对齐** | 适配层产出 `traceRows[]`，长度必须 = `steps.length`，无报文步骤填 `null` 并渲染占位行（`—— 本机操作，无报文 ——`） | **是**（见 §6 D5） |

### 7.3 M2-B — 课程通用性验证（唯一目标：证明"加课只写数据"）

**为什么选 ARP 而不是 DNS 作为第一门新课**：ARP 只有 4 个设备、场景清晰（同网段广播 → 单播应答 / 跨网段交给网关）、且**必然撞上三个真实问题**——`broadcast` 目标、`generic/switch` 设备画法、无报文步骤。撞墙越早越好。

**范围**

| 项 | 内容 |
|---|---|
| B1 ARP 演示 | 1 个 demo、2–3 个场景（same-subnet / cross-subnet / cache-hit），拓扑 4 设备（pc1/pc2/gw/sw1） |
| B2 ARP 知识 | 1 篇 knowledge + 来源（RFC 826、教材章节） |
| B3 适配层泛化 | 仅在撞墙处改：`Device.kind → 美术组件` 映射（替代槽位序）、无报文步骤的占位行、broadcast 是否需要"域内多点"视觉（可先退化为"发送方向多个接收者逐一点亮"） |
| B4 课程切换 UI | 恢复多课入口（侧栏分组 + 课程列表；**搜索与知识图谱仍不做**） |
| B5 通用性度量 | 记录"新增一门课实际改了多少行 `src/`"，作为 M2-C 的准入依据 |

**明确不做**：不做参数输入、不做 ARP 表编辑、不做 VLAN、不做布局自动算法（手工排 4 槽或简单参数表即可）。

**验收标准**
1. 两门课（TCP、ARP）能来回切换，播放/重置/速度/表格/详情全部正常。
2. **新增 ARP 一课，`src/isokit-scene.jsx` 改动 ≤ 30 行且不含 `if (protocol === 'arp')`**；`src/app/demo-view.mjs` 改动 ≤ 80 行。
3. `Device.kind` 与美术组件的映射改为查表，ARP 的 `switch` 能正确画出交换机造型（或明确记录"暂用通用造型"这一妥协）。
4. 无报文步骤（缓存命中、查表）有明确占位行，不报错、不错位。
5. 加一门课的改动清单能写成"3 个 JSON + 1 处注册"，且**清单里没有 `src/` 之外的解释**。

### 7.4 M2-C — DNS 迁移与多设备拓扑（唯一目标：把拓扑承载能力铺开）

> 用户原计划 M2-C 为「ARP、DNS 迁移」。此处把 **ARP 提前到 M2-B**（它设备少、能最早暴露通用性问题），
> M2-C 则承接 **DNS（5 设备）** 与 ARP 的知识内容补齐——迁移总量不变，只是顺序更省返工。

**范围**

| 项 | 内容 |
|---|---|
| C1 DNS 演示 | 5 设备（client / local-dns / root / tld / auth），2 场景（recursive / iterative 或 cache-hit） |
| C2 布局参数化（**前置**） | `POSITIONS` / `NETWORK_POSITIONS` 改为按 `topology` 生成（或每课一张布局表）；`networkRoute` 改按 `links` 求链 |
| C3 多跳链路视觉 | DNS 5 跳的路径不能"穿过"中间设备 → 需要按链路串接的平滑路径 |
| C4 知识补齐 | DNS 1 篇 + ARP 1 篇（若 M2-B 未写完）+ 来源（RFC 1034/1035/826、教材章节） |

**明确不做**：不做 DNS 报文逐字段解析器（`layers` 只做展示数据）、不做"输入域名看解析结果"、不做 5 设备以上的自动布局算法（手工表足够）。

**验收标准**
1. 三门课共用同一播放器，`src/app/app.js` 无协议分支。
2. 5 设备拓扑渲染正确，路径按链路走、不穿越设备体。
3. M2-A/M2-B 的课程零回归（截图 + 冒烟）。
4. 加课清单仍是"JSON + 注册"，无例外。

### 9.1 逐项结论

| 成果 | 建议 | 理由 |
|---|---|---|

| **M2-P0 N1–N7 修复** | **保留，作为"封存的护栏"** | N1（多播真实校验）当前无消费方，但成本已沉没、无维护负担；**不要因为"当前用不到"而回滚** |

### 9.2 不要做的三件事

1. **不要为了"轻量"删掉 `src/engine/`、`src/types/`、`src/schemas/`**：它们是已付成本，删了要重付，而且会连带废掉 65 项测试。
2. **不要为了"架构完整"继续加抽象**：M2-A 只需要一张关系映射表和一次 fold 调用，不需要新的 engine。
3. **不要为了"将来能扩展"提前做拓扑参数化**：M2-A 的 4 槽位够用；等 M2-B 撞墙（DNS 5 设备）时再做，那时才有真实约束。

### 9.3 M2-A 的一个隐性收益（值得写进验收）

`content/` 现在没有任何 `knowledge`/`sources` 数据，所以 X1/X2/X3/X11 与 P1–P7 **全部处于 INFO 跳过状态**（校验器已如实说明）。
M2-A 迁入第一课真实数据后，这批规则**第一次真实执行**——这是数据层从"自测通过"走向"生产可用"的唯一途径，也是 M2-A 不可跳过的深层原因。

## 10. 五项决策：**已确认**（2026-11-12 用户批准）

| # | 决策 | 结论 | M2-A 落地方式 |
|---|---|---|---|
| **D-A** | 7 类关系语义落在哪 | **采用 `demo → viewModel` 适配层映射，不修改核心数据模型** | `src/engine/view-model.ts` 内一张 `EventKind × PacketCat × 发起方 → relation` 查表；`control/check/reject/compare` 当前无消费方，**留空不猜** |

| **D-C** | 伪代码页签 | **第一版不恢复** | 删除 `app.js:58` 死分支；JSON 不迁 `code` 字段；`check-content` 的 `code.length>0` 断言一并移除（这是唯一被删除的旧断言，单独标注） |
| **D-D** | 知识图谱视图 | **第一版不恢复**；但**必须恢复课程目录、搜索、分类、多课程切换等基础导航** | 取回 `#search`/`#all-topics`/`#current-no`/`.parts`，**不取 `#map-*`**；单课时 `hidden`（保像素门禁），多课时自动出现 |
| **D-E** | 布局参数化时机 | **M2-A 不做全局布局参数化**；先验证 ARP 的实际展示需求，必要时在 **M2-B 前**增加最小通用布局能力 | M2-A 只用 4 槽位映射（`participants` 顺序 → 槽位）。**若 M2-B 的 ARP 4 设备（含 switch）仍能落在 4 槽内，则布局参数化继续推迟到 M2-C 的 DNS 5 设备** |

**路线确认**：M2-A TCP → M2-B ARP → M2-C DNS → 内容扩展 → 教学交互增强。
参数实验、协议实时计算、拓扑编辑器、网络模拟器**不进入任何阶段**。

**与 V1.0 建议的差异**：仅 D-E 措辞收紧（"必要时 M2-B 前"而非固定的"M2-C 前置"），其余 4 项按建议原样确认。D-D 追加了"恢复基础导航"的要求，已并入 M2-A 的 A5 工作项。

## 11. 一句话判断标准（写在这里，用于砍掉未来所有争论）

> **"加一门课，是不是只要写一个 JSON、一篇知识、几条来源？"**
> 是 → 架构健康，继续加课。
> 不是 → 停下来补架构，不要靠复制粘贴硬推第三门课。

这条标准同时否掉了两个方向：
- 往"更多抽象"走（加参数、加引擎、加实验）——因为那些都不会让"加课"更便宜；
- 往"更多特例"走（每课一份渲染器、每个协议一个分支）——因为那会让"加课"重新变成开发。
